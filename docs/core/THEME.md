# Thred: Theme

**Purpose:** To define the shared vocabulary, tone, and structural patterns
that every part of Thred — and every component program that joins it —
inherits. Theme sits above program-specific philosophy: it's what makes
a milestone sticker, an alumni coffee chat, and a deployed app all
legible as part of the *same* thread.

Theme is not a game skin. It requires no mascot, persona, or character
voice. Those belong to a separate, optional, future layer — see
[Game Skin Concept](../future/GAME_SKIN_CONCEPT.md).

---

## 1. The Governing Image

A student's path through career preparation is a labyrinth: not because
anything in it is monstrous, but because it is genuinely disorienting —
no map, many dead ends, easy to wander in circles or freeze at the
entrance. What a student needs is not someone to walk it for them, but a
thread that keeps their path continuous and lets them find their way
back to it.

**Implication for design:** every stage, term, and interaction should
either help a student see the labyrinth more clearly, or help them hold
onto the thread. Nothing should personify the labyrinth as an enemy to
defeat — that reintroduces an adversarial framing this project has
deliberately moved away from.

## 2. The Role of "Ariadne"

Ariadne is not a mascot or an AI persona. She's a **role**, shared and
rotating: advisors, faculty, and alumni all hold the thread for students
at different points. Any function in the system that "helps a student see
what's missing" or "hands off wisdom from someone who's been through it"
is playing this role — regardless of whether it's implemented as a human,
a rule engine, or (later, optionally) an AI feature with a name and voice.

## 3. Core Vocabulary

These terms are shared across the entire platform and every component
program. Full definitions live in the [Glossary](GLOSSARY.md); this is
the short form:

| Term | Meaning |
| :--- | :--- |
| **Thred** | The umbrella program; also, informally, "being on the thread" (actively engaged). |
| **Journey** | A student's ongoing path through Thred. |
| **Track** | A target destination in the labyrinth — a career direction with defined skills. |
| **Gap** | The distance between a student's current state and a Track's target. |
| **Artifact** | Verifiable proof of work — the "costly signal" that closes a Gap. |
| **Market GPA** | The single, continuous measure of a student's market readiness, built from verified Artifacts. |
| **Component Program** | Any BYU CS initiative (advising, clubs, alumni groups, milestone programs, etc.) that plugs into Thred. |

## 4. Tone

- **Equipping, not rescuing.** Copy should read like handing someone a
  tool, not doing the work for them.
- **Honest, not hyped.** No promises of guaranteed outcomes. Confidence
  comes from clarity, not exaggeration.
- **Calm, not gamified.** No urgency mechanics, no anthropomorphized
  antagonists, no score-as-spectacle. The labyrinth is disorienting —
  Thred's presence should be the opposite: steady and clear.
- **Institutional, but not cold.** This is a university program that
  multiple stakeholders (including recruiters and parents) will see.
  It should feel credible first, personable second.

## 5. What Theme Is Not

- It is not a visual skin (cyberpunk, terminal/matrix, etc.) — visual
  identity is a separate design decision made in service of this theme,
  not dictated by a prior project's aesthetic.
- It is not a story with characters, stakes, or an ending — see
  [Game Skin Concept](../future/GAME_SKIN_CONCEPT.md) for where that kind
  of representation belongs, explicitly marked optional and future.
- It is not required reading for a component program to *feel* like
  Thred internally — only to *speak* Thred's shared vocabulary at the
  points where it connects to the umbrella (see
  [Partner Template](../partners/TEMPLATE.md)).
